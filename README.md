contract-revision-merge-web

API 契约工作台，带并发编辑保护：服务端按强版本标识（ETag）做条件更新，前端在版本冲突时进行三方合并。

## 并发协议

- `GET /api/contracts/:id` 返回强 ETag（当前修订号，如 `"4"`）。
- `PUT /api/contracts/:id` 必须携带 `If-Match: "<baseRevision>"`：
  - 缺失 → `428`；弱 ETag / 非法值 → `400`。
  - 与当前修订一致 → 保存成功，修订号 +1，返回新 ETag。
  - 不一致 → `409`，响应体含 `base`（客户端开始编辑时的基线）、`latest`（服务端最新内容）和 `conflicts`（冲突字段路径及三方值；删除以缺省键表示）。基线未知时 `base`/`conflicts` 为 `null`。
- `GET /api/contracts/:id/revisions/:rev` 返回历史修订快照，供刷新后重新确认远端版本时取基线。

## 三方合并（`src/shared/merge.ts`，前后端共用）

- 对象递归逐字段合并；数组与原始值按原子值比较（数组重排即该路径的一次变更）。
- 本地与远端变更路径重叠（相等或互为祖先）且在公共祖先处未收敛到相同值时判定冲突——覆盖字段删除、数组重排、父子节点同时变化。
- 未冲突的本地变更自动并入远端结果；冲突由用户逐项选择本地或远端值，解决前禁止普通保存。
- 本地草稿持久化在 `localStorage`；刷新后恢复草稿并重新拉取远端版本，必要时自动进入合并/冲突流程。

## 验证

`npm test` 覆盖：两个客户端交错保存（后者收 409 及 base/latest/conflicts）、无冲突自动合并后重试成功、冲突逐项解决后重试成功、服务端版本再次前进时再次 409 直至按最新版本重试。
